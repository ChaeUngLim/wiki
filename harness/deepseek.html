DeepSeek Harness의 설계: 모든 것이 plugin, 모델이 본 것은 모두 기록

왕초보 설명

  • 이게 뭐야? DeepSeek이 낸 dsh(DeepSeek Harness)를 뜯어본 코스 글이다. 특징은 하네스를 특정 AI 모델에서 떼어 낸 독립 운영체제처럼 만든 것. 모델 연결, 도구, 대화 기록, 심지어 AI가 도는 루프까지 전부 갈아 끼울 수 있는 부품(plugin)이다.
  • 비유: 레고 기본판. 판(커널)은 아무 기능도 없고, 바퀴·엔진·조종석을 전부 블록으로 끼운다. 대신 처음부터 조립할 게 많다.
  • 나는 뭘 하면 돼? 직접 쓰기보다는 설계 아이디어 두 가지를 가져가면 된다. ① “AI가 본 것은 전부 기록한다”. 나중에 왜 그렇게 했는지 되짚을 수 있다. ② 검사·권한·기억 기능을 루프 안에 하드코딩하지 말고 “도구 실행 전” 같은 지점에 끼우는 방식으로 붙인다. 아직 Developer Preview(맛보기 단계)다.

구조 요약

한 문장: 공식 정의 Agent = Model + Environment + Tools + State. 전통적 coding agent가 “LLM + 고정 루프 + 고정 도구”라면, dsh는 “모델 + plugin 커널(Cordis)“이다. 커널은 plugin 로드·언로드·의존성·이벤트만 맡고 agent 능력을 하나도 소유하지 않는다. 아키텍처 문서 인용: “Every part of the product is a plugin, including the model adapter, the tool registry, the session log, and the agent loop itself”, “There is no privileged core to patch”. 2026년 8월 Developer Preview, 저장소 deepseek-ai/deepseek-harness(MIT).

핵심 1: 능력 접합부(capability seam) 후보:capability-seam. 능력마다 세 역할로 나눈다.

Service Definition   (인터페이스 선언)
        ↓
Service Provider     (구현: 예 Local FS / E2B FS / Remote FS)
        ↓
Consumer             (사용자: 보통 모델에 노출되는 도구)

Shell, Subprocess, Sandbox, Web, LLM, SubAgent도 같은 구조다. agent가 “구체적인 도구”가 아니라 “능력 인터페이스”에 의존하므로, Provider를 바꿔도 모델이 보는 도구 모양은 그대로이고 환경만 바뀐다.

핵심 2: 이벤트 파이프라인

turn/start → claim input → assemble(system prompt / context / tools)
  → agent/pre-step → step/start → LLM request(agent/request) → llm/stream
  → assistant/message → tool/call
  → tools/pre-execute(permission / guard / policy / hook)
  → tools/execute → tools/post-execute → tool/result → step/end → next turn

turn/*, step/*, user/message, assistant/*, tool/*는 영속화되는 session 이벤트이고, agent/pre-step, agent/request, llm/stream, tools/*는 plugin이 받는 확장 지점이다. 안전 검사는 tools/pre-execute, 메모리 주입은 agent/pre-step, 모델 요청 수정은 agent/request, 계속 추론할지는 agent/turn-stopping에서 한다. 루프 자체를 고치지 않고 listener로 붙인다. lecture-11의 “관측 가능성은 하네스 안에”보다 더 나아가 루프의 모든 단계를 이벤트 지점으로 만든다.

핵심 3: “Model-visible means logged”. append-only Session Event Log에 대한 런타임 불변 조건이다. “모델 요청에 들어가는 모든 것은 로그에서 재구성할 수 있어야 하며, 런타임 불변 조건이 이를 강제한다.” 로그는 덮어쓰지 않고 추가만 하므로 session 상태를 재생할 수 있다. 원문은 이를 lecture-12의 “클린 상태 인계”를 엔지니어링으로 보장하는 장치로 본다(continuity-artifacts).

원문이 꼽는 참고할 설계: ① 루프의 모든 단계를 이벤트 지점으로 ② 능력 접합부 표준화 ③ Model-visible means logged ④ append-only session 로그.

  • 원문의 대비: Pi·Claude Code·Codex는 “하나의 구체적인 agent” 안에서 하네스를 최적화하고, DeepSeek Harness는 하네스를 모델과 독립된 운영체제로 정의해 agent를 그 위의 교체 가능한 애플리케이션으로 만든다. 대가는 높은 설정 비용.

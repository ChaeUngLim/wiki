Pi의 하네스 설계: 극도로 단순한 커널 + 프로그래밍 가능한 확장

왕초보 설명

  • 이게 뭐야? 스스로를 “minimal agent harness(최소한의 하네스)“라고 부르는 터미널 AI 코딩 도구 Pi를 뜯어본 코스 글이다. 기본 기능은 일부러 적게 두고, 필요한 건 확장(내가 짜 넣는 작은 프로그램)이나 남이 만든 패키지로 붙인다.
  • 비유: 빈 원룸에 이사 가기. 가구가 거의 없지만 원하는 대로 채울 수 있다. 대신 직접 사 와야 한다.
  • 나는 뭘 하면 돼? 프로젝트에 AGENTS.md를 두면 Pi가 읽는다(CLAUDE.md도 읽음). 테스트 같은 확인 명령은 Pi가 강제하지 않으니 AGENTS.md에 직접 적는다. 대화가 길어지면 /compact, 예전 지점으로 돌아가려면 /tree.

구조 요약

한 문장: 커널 최소화 + 확장의 프로그래밍화. 컨텍스트 엔지니어링을 시스템 프롬프트 바깥에 두고, Pi가 사용자 대신 하네스를 정하는 게 아니라 사용자(심지어 Pi 자신)가 하네스를 고치게 한다. 포지셔닝 원문: “Ask Pi to build what you want, or install a package that does it your way”. npm 패키지 @earendil-works/pi-coding-agent.

네 가지 맞춤 계층: 확장(Extensions, 생명주기 이벤트에 붙는 TypeScript hooks) / 스킬(필요할 때 로드하는 능력 패키지, 점진적 공개) / 프롬프트 템플릿(/name으로 펼치는 Markdown) / 테마(TUI 외형).

다섯 하위 시스템으로 보기(원문 매핑 표, 원문이 “주관적 비교용”이라 밝힘)

지시: AGENTS.md 로드 순서는 전역 ~/.pi/agent/AGENTS.md → 상위 디렉터리를 단계별로 → 현재 ./AGENTS.md(CLAUDE.md 호환). SYSTEM.md는 프로젝트별로 기본 시스템 프롬프트를 교체(replace)하거나 덧붙인다(append). 시스템 프롬프트 자체는 극도로 단순하게 두고 규칙은 스킬·확장으로 필요할 때만 나타나게 해, lecture-04의 거대 지시 파일 문제를 피한다(map-not-manual).

상태와 컨텍스트(원문이 가장 자세히 다룸)

  1. 프로그래밍 가능한 compaction: 전략 자체를 확장으로 바꿀 수 있다(주제 기반, 코드 인식 요약, 다른 모델로 요약). 기본 동작은 컨텍스트 오버플로 복구 또는 보존 임계값 초과 시 트리거, 최근 약 2만 token을 남기고 이전 메시지는 “context handoff”로 요약해 단계별 연쇄 압축.
  2. 동적 컨텍스트: 확장이 매 추론 전에 메시지 주입, 기록 필터링, RAG, 장기 메모리를 구현한다. 창에 들어가기 전에 넣고 뺄 것을 정한다.
  3. session 트리: “sessions are stored as trees”. /tree로 과거 노드로 돌아가 이어 가고, 모든 브랜치는 한 파일에. HTML 내보내기·gist 공유. 요약으로 이어 붙이는 대신 구조화된 기록 재생(continuity-artifacts).

도구: 스킬은 “self-contained capability packages that the agent loads on-demand”. 트리거될 때만 상세가 컨텍스트에 들어가 프롬프트 캐시를 깨지 않는다(비용 관점의 설계). 확장(hooks)의 공식 활용 예: 위험 명령 가로채기(permissions gate), 작업 전환 시 코드 상태 checkpoint, 경로 보호(.env 쓰기 금지), 도구 출력 수정 후 전달, 외부(파일 감시·Webhook·CI)에서 메시지를 넣어 agent 깨우기.

피드백: 강제 테스트 gate는 내장돼 있지 않다. 커뮤니티 하네스 pi-agent-harness가 확장으로 피드백 루프를 짠다: session-summary(순환 PROGRESS.md), extract-patterns(LESSONS.md에 교훈 축적), telemetry(token·비용), 그리고 VISION.md·PROGRESS.md·LESSONS.md·STANDARDS.md 파일 체계.

루프 엔지니어링과의 연결: TUI 외에 print/JSON 모드, RPC, SDK 임베딩을 지원해 CI/CD나 다른 프로그램이 같은 하네스를 구동할 수 있다. 원문은 이것을 lecture-13의 “수동 구동에서 자동 루프로”의 전제로 본다(loop-engineering).

원문이 꼽는 참고할 설계: ① compaction 전략을 교체 가능하게 ② session 트리로 단순 요약 대체 ③ 프롬프트 캐시 친화(스킬 필요 시 로드) ④ agent가 자기 하네스를 고칠 수 있게.

oh-my-claudecode(OMC): Claude Code 위에 얹는 무거운 멀티 에이전트 랄프톤 하네스

왕초보 설명

  • 이게 뭐야? Claude Code(Anthropic이 만든 터미널용 AI 코딩 도구)에 끼워 쓰는 **확장 팩(플러그인)**이다. 혼자 일하던 Claude 한 명을 전문가 여러 명이 있는 팀처럼 움직이게 바꾼다. README의 표현으로는 “당신의 Claude가 스테로이드를 맞았습니다.”
  • 랄프톤과 무슨 관계야? OMC의 ralph는 Ralph 루프(목표를 주면 끝날 때까지 스스로 반복)를 그대로 구현한 모드다. AI가 “이제 그만할게요”라고 말하려 하면 **훅(hook, 특정 순간에 자동으로 끼어드는 스크립트)**이 그 종료를 막고 “아직 안 끝났다, 계속해”라고 다시 밀어 넣는다.
  • 왜 “무겁다”고 해? 스킬 48개, 전문 에이전트 19개, 훅 명령 30개(이벤트 11종)가 함께 돈다. 단계마다 다른 에이전트와 다른 크기의 모델을 쓰고, 여러 작업자를 동시에 띄운다. 큰 일을 오래 맡기기에는 강력하지만, 처음 쓰는 사람에게는 무엇이 돌고 있는지 보기 어렵다.
  • 나는 뭘 하면 돼? Claude Code 안에서 세 단계면 시작할 수 있다.

그다음 원하는 걸 말하면 된다. 예: autopilot: build a REST API for managing tasks. 뭘 만들지 막연하면 /deep-interview "만들고 싶은 것"부터 한다.

구조 요약

한 장 그림: 실행 모드 고르기

계속 돌게 만드는 장치: Stop 훅

  • hooks/hooks.json은 Claude Code의 거의 모든 순간(프롬프트 제출, 도구 사용 전후, 하위 에이전트 시작·종료, 압축 직전, 멈춤, 세션 종료)에 스크립트를 건다.
  • 핵심은 Stop(AI가 턴을 끝내려는 순간)에 걸린 persistent-mode.mjs다. ralph·ultragoal·autopilot·team 같은 모드가 켜져 있으면 decision: "block"을 돌려줘 종료를 막고, 남은 일을 다시 지시한다.
  • 무한 루프 방지 상한: 기본 500회. OMC_SECURITY=strict이면 200회로 줄어든다.
  • 안전 예외: 컨텍스트 한도 초과나 인증 실패(401/403)로 멈출 때는 막지 않는다. 다른 Stop 훅이 이미 돌고 있을 때도 다시 막지 않는다(Claude Code의 반복 차단 보호와 충돌하지 않도록).

비유하면, 퇴근하려는 직원을 문 앞에서 “체크리스트 아직 남았어요”라며 돌려보내는 경비원이다.

ralph 한 바퀴

  1. PRD 준비: .omc/state/sessions/<id>/prd.json에 일을 이야기(user story) 단위로 쪼개고, 이야기마다 확인 가능한 완료 기준을 쓴다. 자동 생성된 “구현 완료” 같은 뭉뚱그린 기준은 반드시 구체적으로 바꾼다.
  2. 기준선 기록: 첫 바퀴에 omc ralph verify --write-baseline. 빌드·테스트·린트(feedbackCommands)를 돌려 “원래부터 실패하던 것”을 적어 둔다.
  3. 이야기 하나 구현 → 검증: omc ralph verify가 기준선 대비 새로 생긴 실패만 문제로 본다. AI가 테스트 결과를 눈으로 대충 보고 판단하는 것은 금지다.
  4. 모든 이야기 통과 → 리뷰어 검증: 기본 리뷰어는 architect. --critic=critic 또는 --critic=codex로 바꿀 수 있다. 거절되면 고치고 같은 리뷰어에게 다시 받는다.
  5. 정리(deslop)와 종료. 진행과 배운 점은 progress.txt에 쌓인다.

추가 장치: 측정해 보니 완료 기준이 틀렸다면 몰래 지우지 않고, 원문과 근거를 남기는 “기준 수정 기록(criterionAmendments)“으로만 바꾼다. 저장소 성격(prototype/production/library)에 따라 검증 강도가 달라진다. 사람이 없을 때는 omc ralph afk로 돌린다.

장점 (왕초보 관점)

  1. 시작이 쉽다. 설치 3줄 뒤 “autopilot: 만들고 싶은 것”이라고만 말하면 된다. 명령어를 외울 필요가 적다.
  2. 큰 일에 강하다. 여러 에이전트·여러 회사 AI를 동시에 굴리고, 단계마다 전문 에이전트를 붙인다. 큰 덩어리를 쪼개 병렬로 처리하는 데 맞춰져 있다.
  3. 잘 안 멈춘다. Stop 훅이 “다 했어요”를 막고 완료 기준이 채워질 때까지 다시 돌린다. 완료 기준 자체도 측정 근거 없이 지우지 못하게 기록을 남긴다.
  4. 검증을 기계에 맡긴다. omc ralph verify가 처음부터 실패하던 것과 새로 생긴 실패를 구분해 준다. AI가 결과를 눈으로 보고 “괜찮아 보여요”라고 하는 걸 막는다.
  5. 보이는 게 많다. HUD 상태바, 토큰 사용량 추적, 세션 요약 알림이 있다.

단점과 주의할 점

  1. Claude Code 전용이다. Claude Code 밖에서는 못 쓴다. Codex 중심이면 별도 프로젝트 oh-my-codex를 쓴다(README 안내).
  2. 무겁고 속이 잘 안 보인다. 스킬 48개, 에이전트 19개, 훅 명령 30개가 함께 돈다. 이상하게 동작할 때 어느 훅·스킬 때문인지 찾기 어렵다. 도움말: /omc-doctor.
  3. 모드가 말 한마디로 켜진다. 프롬프트에 매직 키워드가 들어가면 의도보다 큰 모드가 켜질 수 있다. 멈추려면 /oh-my-claudecode:cancel.
  4. 토큰을 많이 쓸 수 있다. 루프 상한이 기본 500회로 넉넉하고, 여러 에이전트를 동시에 띄운다. 예산 상한(OMC_RUN_BUDGET_TOKENS)은 직접 켜야 하는 선택 기능이다.
  5. 준비물이 늘어난다. Team은 Claude Code 실험 기능(CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1)을 켜야 하고, CLI 작업자는 tmux와 codex·gemini CLI 설치가 필요하다.
  6. 문서와 코드가 어긋난 곳이 있다. README의 “32개 에이전트”와 실제 19개처럼, 숫자는 코드로 확인한다.

무겁다는 게 무슨 뜻인가

이 위키에서 “무겁다”는 기능의 양을 뜻한다. 작업 시간을 뜻하지 않는다. 작업자를 여럿 띄우고(team), 단계가 많고(autopilot 6단계), Stop 훅이 최대 500회까지 루프를 붙잡는다. 큰 작업을 사람 없이 오래 굴리는 데 맞춘 설계다.

왕초보에게기본 내장이 많아 바로 쓴다. 확장 4종(스킬·MCP·hooks·subagent)의 역할 구분은 배워야 한다기능보다 규약. 저장소를 잘 정리해 둘수록 효과가 커진다자유도가 가장 높지만 설정 비용도 가장 크다. 아직 Developer Preview가장 가볍지만 필요한 장치는 직접 만들거나 패키지로 설치해야 한다기능이 많아 강력하지만 무겁다흐름이 하나라 배우기 쉽다. 대신 git 필수

고르는 법은 gajae-code 페이지의 선택 표에 정리했다.

  • OMC는 claude-code 하네스 위에 한 층을 더 얹는 구조다. Claude Code가 주는 것은 CLAUDE.md 계층, hooks(Stop·PostToolUse 등), 스킬, subagent, permissions, compaction 같은 부품이고, OMC가 더하는 것은 그 부품으로 짠 ralph·team·autopilot 워크플로, 키워드 자동 감지, .omc/ 상태 파일이다. 특히 OMC의 지속 모드는 Claude Code의 Stop hook 지점을 이용해 턴 종료를 막는다.
  • gajae-code는 NOTICE.md에서 OMC의 워크플로 실험을 계보로 밝힌다. 두 하네스가 deep-interview·ralplan이라는 같은 이름을 쓰는 이유다. 다만 실행 루프는 OMC의 ralph 대신 ultragoal로 바꿨고, 계속 돌게 하는 방식도 Stop 훅 차단이 아니라 goal 모드 연속 실행이다.
